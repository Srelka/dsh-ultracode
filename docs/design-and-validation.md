# 设计与验证

## 实现边界

启动时读取宿主 Loader 的最终 `standard` 声明，保留条件配置和模块解析位置，生成独立 Ultracode 预设。基础声明需包含原生工作流工具与独立工作流引擎组；缺少必要接口时显示不可用诊断，不静默回退到陈旧配置。

执行复用 DSH 的原生工作流、后台任务和会话日志。历史投影从已有事件生成，不增加私有会话事件类型。已有会话恢复时，运行时已不存在的任务标记为中断。

浮动卡片使用原生 `conversation.composer.dock`。模式微光使用 `conversation.input.overlay`，读取原生 `agentPreset` 投影；仅通过 `data-composer-card` 语义锚点测量尺寸与圆角，不修改宿主输入框。宿主变更该锚点时，光效可能失效，需要重新适配。

开场 1.8 秒，无光间隔 0.35 秒，微光淡入 1.1 秒，呼吸周期 5.6 秒。常驻微光使用连续渐变，无点状灯珠。模式切换、页面隐藏和组件卸载均清理或暂停相应动画资源。

## 1.2.1 预设切换修复

旧版仅在 agent/created 时注册编排能力，空白标准会话切换到 Ultracode 不会重新创建 Agent，因而可能只有界面切换。1.2.1 同时处理 agent-preset/selected，按当前预设版本的作用域核对归属，切入时安装、切出时清理，并防止重复注册。创建和恢复会话沿用同一初始化逻辑。

模型在 Ultracode 下自行判断复杂度：复杂任务主动创建工作流，简单任务直接处理。选择预设就是编排授权。标准预设保持宿主原有规则。宿主只允许空白会话切换模式的限制不变。

Zod 更新至 4.6.6，解决安装审计报告的集合校验内存消耗公告；当前包 npm audit 为零漏洞。

## 已完成的验证

基于 DSH Desktop 0.2.1-rc.2，35 项自动化测试通过。控制器契约测试覆盖取消、重入、恢复、减少动态效果、尺寸变化和资源释放；这些测试不替代真实视觉验收。

实际 DSH Web UI 验证了模式切换、无光间隔与淡入、取消后不重亮、历史会话、输入增高、430px 窄屏、浅色与深色、模型推理强度选择，以及工作流卡片交互。

独立确定性测试适配器完成两代理并行、第三代理复核、后台结果唤醒和历史恢复。该测试未消费真实模型账户，不代表所有模型的规划质量或其他操作系统均已验证。

1.2.1 新增测试使用真实宿主的作用域、事件分发、提示与工具注册表，覆盖首次切入、来回切换、重复选择、多会话隔离、恢复根代理/工作代理及卸载清理。实际页面还验证切换后的首条请求、简单问题不启动工作流、两代理并行加独立复核、后台唤醒、切回标准与重启恢复。离线适配器只用于执行链路验证，不代表真实模型必定作出正确拆分。

## 发布边界

本仓库不包含个人 profile、会话记录、模型配置、认证信息、机器专用启动器或解包的 DSH 运行时。没有安装时执行脚本。升级 DSH 后应复查宿主 API 与客户端槽位兼容性。
